# Sentinel — мультиагентна система оцінки ситуаційної небезпеки

Програмний продукт переддипломної практики й магістерської роботи Дмитра (КПІ ім. Ігоря Сікорського).
**Захист програмного продукту — 12.10.2026.** Повна специфікація — `docs/SPEC.md`; це джерело істини.
Розділ «Зафіксовані рішення» в ній не змінюй без явного дозволу Дмитра.

## Суть за 30 секунд

Відео (вебкамера / RTSP / файл) → агенти ознак (детекція людей і зброї, трекінг, поза та взаємодія, контекст зони)
→ **опис сцени** (pydantic → JSON) раз на ~1 с → агрегатор **A** (логістична регресія + правило «зброя в руці»)
і/або агрегатор **B** (LLM, лише текст, строгий JSON) → **каскад** (B тільки в сірій зоні A) → автомат інцидентів
→ одне повідомлення в Telegram на інцидент, яке далі редагується.

Наукова суть — чесне порівняння `baseline` / `A` / `B` / `cascade` на **ідентичних** описах сцени.
Усе, що робить входи A і B різними, заборонено.

## Середовище

- **Ubuntu**, Lenovo IdeaPad Pro 5 14IRH8: Intel Core 13-го покоління (серія H), **лише вбудована Intel Iris Xe — NVIDIA немає**.
  Усі обчислення на CPU; Intel iGPU — тільки через OpenVINO і тільки якщо замір це виправдає
  (для iGPU в OpenVINO потрібен Intel compute runtime з apt — це `sudo`, тож лише за погодженням із Дмитром).
- Python 3.12 через `uv` (`uv sync`, `uv run`, `uv.lock` у git).
- **PyTorch — лише CPU-збірка.** На Linux звичайний PyPI тягне CUDA (гігабайти зайвого), тому `torch` і `torchvision`
  беруться з індексу `https://download.pytorch.org/whl/cpu` через `[[tool.uv.index]]` (`explicit = true`) і `[tool.uv.sources]` у `pyproject.toml`.
  Те саме — у Docker-образі.
- Команди, що потребують `sudo` (apt), не виконуй сам — дай Дмитру готовий рядок і чекай підтвердження.
- Docker є. На Linux вебкамеру можна прокинути в контейнер (`--device /dev/video0`), тож демо з камери працює і в Docker.
- Репозиторій — у `~/dev/sentinel` (або де його розпакував Дмитро); набори даних займають десятки ГБ — перевіряй вільне місце.

## Залежності — мінімум (це вимога)

- Runtime: `ultralytics`, `pydantic`, `scikit-learn`, `python-dotenv`, `openvino` (бекенд моделей, рішення 30.09),
  `lap` (потрібен ByteTrack в ultralytics, рішення 29.09). numpy, opencv, requests, pyyaml приходять з ultralytics — користуйся ними.
- Dev: `pytest`, `ruff`.
- Заборонено: LangChain, LangGraph, Streamlit, python-telegram-bot, aiogram, SDK LLM-провайдерів (openai, google-genai тощо),
  бази даних, веб-фреймворки, click/typer (CLI — `argparse`).
- Telegram і LLM — прямі HTTP-запити через `requests`. LLM-провайдери OpenAI-сумісні: `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` у `.env`.
- Будь-яка нова залежність — лише через «Потрібне рішення» у звіті.

## Код

- src-layout, структура — `docs/SPEC.md`, розділ 10. CLI `sentinel` (`run` / `bench` / `eval`) через `[project.scripts]`.
- Код, ідентифікатори, коментарі, коміти — англійською. Тексти для людини (`reason_uk`, повідомлення в Telegram) — українською.
- Type hints скрізь. Усі контракти між агентами — pydantic-моделі в `schema.py` із `schema_version`.
- Пороги, частоти, розміри входу — у `configs/default.yaml`, не в коді. Секрети — лише `.env`.
- Опис сцени: відстані й швидкості нормовані на зріст людини, значення округлені до 2 знаків (SPEC, розділ 5).
- Реальний час (SPEC, розділ 6): читач найсвіжішого кадру, жодних черг кадрів; LLM ніколи не на критичному шляху.
- Тести (pytest) для схеми, ознак (на синтетичних ключових точках), агрегатора A, автомата інцидентів. У тестах моделі не завантажувати.
- Детермінізм: фіксовані seed; відповіді LLM кешуються в `cache/llm/` і зберігаються разом із результатами.

## Дані й артефакти — поза git

- `data/raw/<набір>/` — сирі набори; `data/episodes/` — епізоди; `weights/` — ваги; `results/` — журнали й метрики; `cache/llm/` — кеш LLM.
- `data/SOURCES.md` **комітиться**: для кожного набору й кожних ваг — URL, офіційне джерело чи дзеркало, ліцензія/умови,
  дата завантаження, розмір, кількість файлів. Це піде у звіт.
- Ліцензії наборів — лише дослідницьке використання: не поширювати, не комітити відео чи кадри з людьми.
- **RWF-2000**: офіційно недоступний (автори прибрали відео з міркувань приватності; запит авторам надіслано).
  Беремо дзеркало Hugging Face `DanJoshua/RWF-2000`, зберігаємо оригінальний поділ train/val.
- **XD-Violence**: потрібні лише тестові відео й розмітка тесту. Офіційно — посилання OneDrive на https://roc-ng.github.io/XD-Violence/;
  якщо з терміналу не скачується — дзеркало (Kaggle / Hugging Face), із позначкою в `SOURCES.md`.
- **Зброя на відео (Севілья)**: https://github.com/Deepknowledge-US/US-Real-time-gun-detection-in-CCTV-An-open-problem-dataset
- Перед кожним великим завантаженням перевір вільне місце на диску.

## Секрети

- Лише `.env` (у `.gitignore`); `.env.example` — з порожніми значеннями.
- Kaggle-токен у Дмитра вже є (`~/.kaggle/kaggle.json` або змінна `KAGGLE_API_TOKEN`) — перевір, де саме, не виводячи значення.
- Ніколи не друкуй значення ключів у консоль, логи, звіти чи коміти.

## Чого не робити

- Не передавати в LLM зображень. Не розпізнавати облич. Не додавати сценарії поза «зброя + агресія».
- Не підбирати пороги й гіперпараметри на тестовій частині — лише на валідаційній.
- Не вигадувати цифр у звітах — тільки виміряне; якщо не виміряно, так і пиши.
