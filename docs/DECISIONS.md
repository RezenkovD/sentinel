## 29.09.2026 — рішення за звітом сесії 01

Підстава: [`docs/reports/01-setup.md`](reports/01-setup.md), розділ 9.

1. **`lap` — залежність проєкту.**
   - *Чому:* ByteTrack в Ultralytics імпортує `lap` на рівні модуля; без нього трекінг не працює, а запуск через
     `--with lap` не фіксує версію й не працює в Docker.
   - *Змінилось:* `lap` у `dependencies`, версія — в `uv.lock` (0.5.13). `YOLO_AUTOINSTALL=false` лишається.
     README більше не згадує `--with lap` (звіти замірів 28.09 лишаються як історичний запис).
2. **Люди й поза — YOLO26n (detect + pose), `imgsz` 480, частота аналізу 10 кадрів/с.**
   - *Чому:* на 480 — 42 мс/кадр, RTF@10 = 0,43, затримка ~60 мс, лишається запас під детектор зброї.
     Покриття позою в YOLO26n вище, ніж у YOLO11n (80 % проти 74 %).
   - *Змінилось:* дефолти в `configs/default.yaml`, SPEC §6.
3. **OpenVINO не додаємо.**
   - *Чому:* без нього RTF ≤ 1 із запасом.
   - *Змінилось:* нічого, крім SPEC §6. OpenVINO — резерв, якщо повний конвеєр дасть RTF@10 > 0,8.
4. **Живлення: демо й випробування — лише від мережі, профіль `performance`.**
   - *Чому:* на батареї в профілі `balanced` обробка вдвічі повільніша (RTF@10 = 1,54 при 640).
   - *Змінилось:* `sentinel bench` записує в кожен рядок джерело живлення (`/sys/class/power_supply`) і профіль
     (`powerprofilesctl`), показує їх у таблицях і не змішує прогони з різним живленням; SPEC §6.

## 29.09.2026 — опис сцени, схема v2 (сесія 02)

- **Рішення:** `schema_version = 2`.
  - `speed`, `limb_accel`, `approach_speed`, `facing` і `crowd_motion` можуть бути `null` («не обчислено»),
    замість вигаданого нуля. Приклади: немає скелета, трек видно лише в одному кадрі вікна, немає точок носа
    й плечей у пари, ніхто зі швидкістю не відомий.
  - `holds` набуває значень `gun` / `knife` (було `pistol` / `knife`): пістолет і гвинтівка зводяться в `gun`.
- **Чому:** завдання сесії 02 вимагає `null` для відсутніх ознак і класи `gun` / `knife`, а схема v1 не дозволяла
  ні того, ні іншого. Зміна полів означає нову версію (SPEC §5): описи v1 не приймаються як v2.
- **Змінилось:** `src/sentinel/schema.py`, тести схеми. Порожня сцена лишається валідною
  (`n_persons 0`, `crowd_motion 0.0`).

## 29.09.2026 — агрегатор A v0: ознаки й відсутні значення (сесія 02)

- **Рішення.** `scene_to_features` дає 13 ознак у фіксованому порядку: 12 із завдання + індикатор
  `limb_accel_missing`.
  - Порядок: `n_persons`, `crowd_motion`, `max_speed`, `max_limb_accel`, `min_distance_h`, `max_approach_speed`,
    `facing_close`, `max_contact_s`, `n_close_pairs`, `weapon_visible`, `weapon_held`, `zone_prior`,
    `limb_accel_missing`.
  - `null` → нейтральне значення з конфігу («спокійна сцена»): 0 для швидкостей, прискорень, контакту й
    лічильників, 2,0 зросту для `min_distance_h` (нікого поруч).
  - Індикатор відсутності — лише для прискорення зап'ясть. Якщо ні в кого немає трьох упевнених точок зап'ястя,
    це «немає даних про руки», а не «спокійні руки». Для решти `null` рідкісний або нейтральне значення
    збігається за змістом.
  - `facing_close` рахує лише `facing = true` у парах, ближчих за `contact_distance_h`.
  - `zone_prior` = сума таблиць за годинами, щільністю й типом зони.
- **Модель.** `risk = sigmoid(bias + Σ w·clip((x − mean)/scale, ±5))`. Ручні ваги й масштаби (v0) — у
  `configs/default.yaml → aggregator_a`, `mean = 0`. `fit` / `save` / `load` зберігають `mean` / `scale` / ваги
  разом зі списком ознак; завантаження ваг для іншого набору ознак — помилка.
- **Перекриття.** Зброя в руці → `risk ≥ θ_high + 0,1`. Зброя лише в кадрі — звичайна ознака.
- **Пояснення.** 2–3 найбільші внески `w·(z − z_нейтр)` відносно спокійної сцени, українською, з десятковою комою.
- **Чому.** Завдання сесії 02; індикатор і нейтральні значення не дають A сприймати відсутність даних як спокій.

## 29.09.2026 — ручні ваги A v0.1 за санітарною перевіркою (сесія 02)

- **Підстава.** Санітарна перевірка (лише наш train RWF), по 20 Fight + 20 NonFight кліпів, режим offline.
  Підбір — на вибірці `seed 2026`, перевірка — на неперетинній вибірці `seed 2027`.
- **Що показали ваги v0.**
  - На рівні вікон ризик A слабко відділяє бійки від норми: AUC 0,55 (2026) / 0,58 (2027).
  - Окремі ознаки (AUC на вікнах із людьми, 2026): `crowd_motion` 0,68, `max_speed` 0,68, `max_limb_accel` 0,49
    (шум: при 10 кадрах/с скінченні різниці підсилюють тремтіння ключових точок, медіана ~10 зростів/с² в обох
    класах), `max_contact_s` 0,40 (обернено: спокійні групи довше стоять поруч).
  - Зсув лише `bias` не допомагає: NonFight росте швидше за Fight.
- **Зміна:** `crowd_motion` 0,3 → 0,8; `max_speed` 0,3 → 0,8; `max_limb_accel` 1,2 → 0,4; `max_contact_s` 0,6 → 0;
  `bias` −2,5 → −1,5. Решта ваг без змін.
- **Результат на перевірочній вибірці 2027:**
  - AUC вікон 0,58 → 0,63;
  - високих вікон (≥ θ_high) у Fight 25 % → 24 %, у NonFight 8 % → 2 %;
  - кліпів із «3 з 5 високих» (лише агресія) у Fight 3 → 3, у NonFight 1 → 0.
- **Обмеження.** 5-секундні кліпи дають лише 5 вікон, тож «3 з 5» — сувора умова. Це ручні ваги до логістичної
  регресії наступної сесії; `limb_accel` потребує згладжування траєкторій зап'ясть.
- **Змінилось:** `configs/default.yaml → aggregator_a`, тест монотонності без тривалості контакту.

## 30.09.2026 — сприйняття v3 і схема v3 (сесія 03, крок 2)

- **Рішення** (завдання сесії 03): ознаки руху, що відрізняють бійку від бігу й не залежать від детекції людей.
- **Схема v3** (`schema_version = 3`; нові поля за замовчуванням `null`):
  - особа: `limb_speed` — p90 швидкості зап'ясть відносно середини плечей, зрости/с; `limb_accel` — тепер найбільше
    **згладжене** прискорення зап'ясть **відносно середини плечей**, зрости/с²; `pose_motion` — середня швидкість
    упевнених ключових точок відносно середини плечей, зрости/с; `motion` — середня абсолютна різниця сусідніх
    кадрів аналізу в рамці людини, рівні сірого (0–255);
  - сцена: `motion_energy` — середня абсолютна різниця кадрів, рівні сірого; `motion_area` — % пікселів, що
    змінилися більше ніж на `motion.threshold` (15).
- **Реалізація (рішення Claude Code):**
  - Траєкторії точок згладжуються локальною регресією за реальними `t`: пряма з ≥ 3 точок для швидкості, парабола
    з ≥ 4 точок для прискорення, до `smooth_points: 5` сусідів; через пропуски > `max_gap_s: 0,3` с не
    інтерполюється. Майбутніх кадрів поза вікном немає; останні 2 кадри попереднього вікна — контекст для
    підгонки на початку вікна.
  - **Центр тулуба — середина плечей:** стегна часто перекриті, а центр із точок, що з'являються й зникають,
    стрибав би й вигадував рух.

## 30.09.2026 — кеш описів сцени й епізоди (сесія 03, крок 3)

- **Рішення** (завдання сесії 03): сприйняття проганяється один раз на епізод (`sentinel eval extract`, режим

  XD-Violence — підвибірка тесту `data/splits/xd_subset.json`.
