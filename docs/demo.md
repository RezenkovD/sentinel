# Показ на захисті програмного продукту (12.10.2026)

**Формат захисту** — презентація на 5 хв **без запуску програми**. Числа й кадри для слайдів:
- кадри — `results/demo/frames/` (опис у `frames.md`);
- числа — `numbers.md` пакета `results/thesis_pack_<дата>.zip`.

Нижче — лише **запасний показ**, якщо комісія попросить. Рівні від простого до складного; кожна команда
перевірена 10.10. Відео й кадри з людьми лежать у `results/` поза git: показувати можна, поширювати не можна.

## 0. За 10 хвилин до захисту

```bash
scripts/demo_check.sh          # кожен рядок OK / FAIL, секретів не друкує; код виходу = кількість FAIL
```

Скрипт перевіряє:
- живлення від мережі й профіль `performance`, load average < 2;
- `/dev/video0`;
- наявність (не значення) `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_IDS`, `GROQ_API_KEY` у `.env`;
- бот відповідає (`getMe`), Groq досяжний (список моделей, токени не витрачаються);
- демо-відео й `1_fight_src.mkv` на місці;
- образ `sentinel:dev` існує;
- SHA-256 ваг збігаються із заморожуванням 04.10;
- `sentinel-b` не працює.

Типові FAIL і що робити:
- **профіль** — `powerprofilesctl set performance`;
- **живлення** — підключити зарядку;
- **load** — закрити Docker-тести інших проєктів і зайві вкладки браузера.

**Прогін B на val завершено 08.10** (600 / 600 вікон), сервіс `sentinel-b` неактивний і більше не викликає Groq,
тож уранці 12.10 зупиняти нічого не треба (Б5). Якщо він раптом активний — до кінця захисту
`systemctl --user stop sentinel-b.timer sentinel-b.service`, після — `systemctl --user start sentinel-b.timer`.

**Про рівень 3.** `1_fight_src.mkv` — чотири оригінальні кліпи тієї самої сцени (N1 → F0 → F1 → N0, наш train
RWF-2000 `JwTPruSFTjk`), склеєні без втрат (FFV1). Конвеєр бачить чисті кадри, а не відео з оверлеєм.

Режим **без `--paced`** детермінований:
- щоразу ті самі кадри, тривога на 12,0 с, закриття на 19,9 с;
- перевірено двічі поспіль 10.10, обидва прогони однакові й збігаються з демо-відео.

Режим **з `--paced`** (у темпі камери, 20 с) на цій сцені нестабільний, бо сцена на межі порога:

| Умови 10.10 | Аналіз | Інцидент відкрився |
|---|---|---|
| `balanced`, від мережі, з PyCharm і браузером | ≈ 7 кадрів/с | 0 з 2 |
| `performance`, на батареї | ≈ 9,3 кадрів/с | 3 з 5 (о 11-й с, закриття спокоєм о 18-й) |

На захисті беремо режим без `--paced`.

Перебудувати `1_fight_src.mkv` (≈ 5 с):

```bash
uv run python -c "from pathlib import Path; from sentinel.eval.protocol import joined; \
R=Path('data/raw/rwf2000/train'); joined([R/'NonFight/JwTPruSFTjk_1.avi', R/'Fight/JwTPruSFTjk_0.avi', \
R/'Fight/JwTPruSFTjk_1.avi', R/'NonFight/JwTPruSFTjk_0.avi'], Path('results/demo')).rename('results/demo/1_fight_src.mkv')"
```

**Рівень 4 у Docker** — той самий образ, що в протоколі випробувань:

```bash
docker run --rm --user "$(id -u):$(id -g)" --env-file .env --device /dev/video0 --group-add video \
  -v "$PWD/weights:/app/weights:ro" -v "$PWD/results:/app/results" sentinel:dev run --source 0
```

## 3. Якщо щось не спрацює

| Що сталося | Що робимо |
|---|---|
| Вебкамера не відкривається (`camera / stream unavailable`) | Рівень 3 замість 4 |
| Немає інтернету / Telegram не відповідає | Рівень 1: повідомлення видно у відео праворуч; у рівні 3 без мережі — консоль замість бота (`TELEGRAM_TOKEN= uv run sentinel run --source results/demo/1_fight_src.mkv`) |
| `/mode B` або каскад: відповідей немає | Безкоштовний ліміт Groq; у живому режимі B ніколи не блокує конвеєр, вікна лишаються за A. Повернути `/mode A` |
| Ноутбук гальмує (кадри пропускаються) | `scripts/demo_check.sh`: живлення, профіль, навантаження |
| Програвач не відкриває `.mp4` | Брати `*_h264.mp4`, відкривати через `mpv` або браузер |
